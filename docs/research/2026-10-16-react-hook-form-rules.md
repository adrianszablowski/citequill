# How React Hook Form, Zod and Base UI want a form written

Research date: 16 October 2026. Prompted by the owner's review of the page editor: `const form = useForm()` and a `useState` for pending and error are not how React Hook Form is used. Installed versions: react-hook-form 7.90.0, @hookform/resolvers 5.9.1, zod 4.6.7, @base-ui/react 1.9.0, next 16.4.0, react 19.3.0.

Sources and grades: A the library's own documentation read from its source (react-hook-form.com returned 403 to a fetch, so its docs were read from the `react-hook-form/documentation` repository on GitHub, `src/content/docs/`, and from the JSDoc and source in `node_modules/react-hook-form`; a path `docs/<page>.mdx` below is the page `https://react-hook-form.com/docs/<page>`, and `advanced-usage.mdx` and `faqs.mdx` are `https://react-hook-form.com/advanced-usage` and `https://react-hook-form.com/faqs`); A the `@hookform/resolvers` README in `node_modules`; A the Next.js 16.4 docs in `node_modules/next/dist/docs`; A the Base UI docs in `node_modules/@base-ui/react/docs`; A react.dev; B ui.shadcn.com, the component vendor's example, which shows a shape rather than states a rule.

## The short answer

React Hook Form holds every state a form has: `isSubmitting` while the submit handler runs, `isSubmitSuccessful` after it, `isDirty` against `defaultValues`, `errors` including a `root` error the server sets. Reading them costs a render only where they are read, because `formState` is a Proxy that subscribes to the fields read during render. A `useState` beside it for pending or error is a second copy that re-renders the whole form. The pieces that stay outside the library are UI modes: whether a dialog is open, whether the editor shows a preview.

## What this means for Citequill

- A form component destructures `control`, `handleSubmit`, `setError`, `reset` and the `formState` fields it renders from `useForm({ resolver: zodResolver(schema), defaultValues })`, with no generic.
- Pending is `isSubmitting`. A form whose action redirects also reads `isSubmitSuccessful`, because the action's call settles before the new page paints and the button must stay pending through it.
- The action's `{ error }` becomes `setError('root', { message })`; its `{ values }` becomes `reset(values)` inside the handler.
- A submit button in its own file takes `control` and reads `useFormState({ control })`, so the parent does not subscribe to `isDirty` or `isSubmitting` for it.
- A live value for a preview comes from `useWatch({ control, name })` inside the component that renders it.
- `useState` keeps UI modes only: a dialog open, a preview shown.
- A fieldless form stays native: `<form action={action}>` with a `useFormStatus` button.
