# Next.js 16.4: what changed and what it means for Citequill

As of 14 October 2026. The project runs on Next.js 16.4.0 and React 19.3.0. Sources: the Next.js blog posts on 16.1, 16.2, 16.3 and 16.4, the documentation bundled with the package in `node_modules/next/dist/docs/`, Vercel's documentation on Runtime Cache, the React 19.3 announcement.

## The model in one paragraph

Cache Components is the new App Router model and from 16.4 Vercel recommends it for every application. It will be the default in Next.js 17, and the `cacheComponents` and `partialPrefetching` flags will go away. Everything is dynamic until you say otherwise. Request data (`cookies()`, `headers()`, `searchParams`, `params`) is read behind `<Suspense>`, and what should be fast and shared is marked with `'use cache'` and `cacheLife`. From this Next.js builds three stages of navigation: the App Shell (one per route, loaded by every `<Link>`), a prefetch per link (`<Link prefetch={true}>`, adds content that depends on the URL) and the navigation (the rest, after the click). In dev every page is checked for whether navigating to it is instant; an error in the overlay says what blocks it.

## Rules that are easy to break

- Every `'use cache'` gets a `cacheLife`. Without it the `default` profile applies (5 min stale, 15 min revalidate), and `ensureStatic = 'navigation'` rejects `expire` below 5 minutes and `stale` below 30 seconds.
- The cache key is the arguments and the variables from the closure, in plain text. Tags too. No tokens, passwords or emails in the arguments of a function with `'use cache'`.
- `generateMetadata` on a page that is otherwise fully static throws an error when it reads uncached data. The fix: `'use cache'` on `generateMetadata`.
- A session read at the top of a layout holds `{children}` behind the request. Read the session in a component behind `<Suspense>`, not in a top-level `await` in the layout.
- `await params` in a layout outside `<Suspense>` ties the App Shell to one URL. Pass the `params` promise down and resolve it in a component behind the boundary.
- GET route handlers are prerendered when they read no request data and no uncached sources. `headers()` in a handler moves it to request time.
- `Math.random()`, `Date.now()`, `crypto.randomUUID()` in prerender run once per build. `await io()` before them or `'use cache'` around them.
- Prefetch works only in production. In dev navigations are not instant, but the validation shows what will block after `next start`.
- Unknown slugs: from 16.3 a route with `generateStaticParams` serves the App Shell for an unknown parameter immediately, renders the rest in the background and saves it to ISR. With `ensureStatic = 'navigation'` the first request waits for the full page.

## What this means for Citequill

Implications, not decisions. The decisions will come in round 2.

### A dashboard with login

- The session is read through `cookies()` in one function such as `getCurrentUser()` with `'use cache: private'`, behind `<Suspense>`. Redirects (`redirect('/login')`) are not cached, only the resolved user is.
- Per-user data: a non-exported `'use cache'` function takes `userId` and tags with `cacheTag(\`projects:${userId}\`)`. The exported getter resolves the user and calls it. This closes off access to another user's data by swapping the id.
- Data from Search Console for the analytics tab: `'use cache: remote'` with `cacheLife` and a tag per project. Plain `'use cache'` on Vercel disappears with the instance, and the Search Console API limit is 1,200 queries per minute per property, so a persistent cache is mandatory. An entry has a 2 MB limit, so large reports have to be cut per page or per date range.
- Mutations (a new skill, a change of project mode) as Server Actions with `updateTag`, not `revalidateTag`, because the owner should see the save at once. The action reads the session itself and does not trust the client.
- The dashboard does not get `ensureStatic`. It is dynamic by definition. The static parts (navigation, skeletons) will enter the App Shell anyway.

### Content API for customer sites

- A GET handler that checks the API key in `headers()` runs at request time. The content lookup behind it goes into `'use cache: remote'` with a tag per site, for example `site:{id}`. Publishing a page calls `revalidateTag(\`site:${id}\`, 'max')`, so the old data goes to the customer until the fresh data is generated.
- The response can also carry `Cache-Control: public, s-maxage=60`, so that Vercel's CDN takes repeated reads off the function.

### A package for customer sites

- The customer has any version of Next.js. The Trackist landing page runs on 16.3.5. The thin route files must work with `cacheComponents` and without it, so the two template variants from the Vercel research stay current: `fetch` with a tag and `revalidate` for the old model, `'use cache'` with `cacheLife` and `cacheTag` for the new one.
- `export const prefetch = 'partial'` on the `/blog/[slug]` segment lets the customer's site take the App Shell for that one route without turning on the global flag.
- An unknown slug (a new page released after the customer's build) gets the App Shell immediately from 16.3, then an upgrade in the background. Links to such pages need `prefetch={true}`, because the default `<Link>` fetches only the shared shell.
- An open question for round 2 or the package design: what a `'use cache'` function that throws on a 5xx from our API does with the old entry. The old ISR advice "throw to keep the stale entry" needs checking under the new model before the package design is final.

### Citequill's public pages (later)

- Landing page, pricing, documentation: `ensureStatic = 'navigation'` on their layout, `generateStaticParams` with the full set of parameters, `'use cache'` on `generateMetadata`. Never on the dashboard layout.

### Repo settings to consider in round 2

- `experimental.agentFeedback: true`: create-next-app with the recommended settings turns this on by default; our scaffold does not have this line.
- `reactCompiler: true` and `typedRoutes: true`: enabled on 14 October 2026, decision in `docs/decisions.md`.
- The `code-style.md` rule should name the patterns from this document (Suspense around request data, `cacheLife` with every `use cache`, `updateTag` in actions) when the first server code appears.
