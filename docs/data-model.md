# Data model

Postgres in one Supabase project, separate from the owner's other applications. Access only from the server. TypeScript types come from `supabase gen types`, never by hand. Every table except `users` has `project_id`; it is the only boundary between projects.

The column names below are concepts, not SQL. The migration implements them; when they differ, the migration is wrong.

## User and project

| Table             | Columns                                                                                                                                                                                                                                                                                                                                                                                                            |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `users`           | `id` (from Supabase Auth), `email`, `created_at`                                                                                                                                                                                                                                                                                                                                                                   |
| `projects`        | `id`, `user_id`, `name`, `domain`, `mode` (`drafts`, `auto`), `pages_per_week`, `run_day`, `run_hour_utc`, `external_links`, `competitors` (list of URLs), `webhook_url`, `webhook_secret`, `indexnow_key`, `indexnow_verified_at`, `site_key_hash` (Content API), `site_id` (public, analytics script), `organization_name`, `organization_url`, `organization_logo_url`, `search_console_property`, `created_at` |
| `project_locales` | `id`, `project_id`, `locale`, `base_url` (origin and optional prefix), `is_default`                                                                                                                                                                                                                                                                                                                                |
| `authors`         | `id`, `project_id`, `name`, `title`, `url`                                                                                                                                                                                                                                                                                                                                                                         |
| `page_kinds`      | `id`, `project_id`, `name`, `url_prefix`, `skill_id`, `author_id`                                                                                                                                                                                                                                                                                                                                                  |
| `skills`          | `id`, `project_id`, `name`, `description`, `body` (markdown), `is_product`, `updated_at`                                                                                                                                                                                                                                                                                                                           |
| `crawled_pages`   | `id`, `project_id`, `url`, `locale`, `title`, `body` (markdown), `crawled_at`                                                                                                                                                                                                                                                                                                                                      |

The Content API key is shown once when it is created and stored as a hash. `site_id` sits in the HTML of the customer's site, so it is public and authorizes nothing.

## Pages

| Table   | Columns                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pages` | `id`, `project_id`, `kind_id`, `locale`, `slug`, `translation_group_id`, `status` (`draft`, `published`, `unpublished`), `title`, `meta_title`, `meta_description`, `excerpt`, `body_md`, `body_html`, `faq` (list of question and answer), `sources` (list of title and URL), `tags`, `author_id`, `reading_minutes`, `check_note`, `redirect_to`, `run_id`, `published_at`, `updated_at`, `unpublished_at`, `created_at` |

Locale versions of one page share a `translation_group_id`; the API derives `translations` from it. The full path of a page is not a column: it is the locale's `base_url` plus the kind's `url_prefix` plus the `slug`, computed in one place in the code. `body_html` is produced from `body_md` at publishing. `check_note` is empty when the page passed the check. `redirect_to` is empty for 410 and filled for 301; only `unpublished` pages have it, so the list of redirects is a query, not a table.

## Runs and reports

| Table     | Columns                                                                                                                                                                                                                                                                         |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `runs`    | `id`, `project_id`, `trigger` (`weekly`, `manual`), `topic` (for `manual`), `kind_id` (for `manual`), `status` (`running`, `finished`, `failed`), `plan` (topics with reasoning and sources), `input_tokens`, `output_tokens`, `cost_usd`, `error`, `started_at`, `finished_at` |
| `reports` | `id`, `project_id`, `run_id`, `week_start`, `body_md`, `created_at`                                                                                                                                                                                                             |

Every model call adds its tokens and cost to its run. This is the only place the report and a future spending limit read the cost from.

## Analytics

| Table                 | Columns                                                                                                                                                                                                                                                                                                             |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `events`              | `id`, `project_id`, `occurred_at`, `visitor_hash`, `name` (`pageview` or the name of a custom event), `path`, `page_id` (when the path is a Citequill page), `referrer`, `referrer_group` (`search`, `ai`, `social`, `site`, `direct`), `country`, `utm_source`, `utm_medium`, `utm_campaign`, `amount`, `currency` |
| `search_console_rows` | `project_id`, `date`, `query`, `page`, `country`, `clicks`, `impressions`, `position`; primary key from the first five columns                                                                                                                                                                                      |

`events` is partitioned by the month of `occurred_at`. `visitor_hash` is a SHA-256 of the daily salt, IP, user agent and `site_id`; the salt is an HMAC of the server secret and the date, so there is no salt table, and yesterday's visitor cannot be linked to today's. `amount` and `currency` are empty in the MVP and wait for revenue from the backlog.
